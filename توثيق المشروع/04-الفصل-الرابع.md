## 1. تصميم قاعدة البيانات

### 1.1 نظام الإدارة والأسلوب

| البند | القيمة |
|---|---|
| نظام قاعدة البيانات | Microsoft SQL Server (LocalDB أثناء التطوير، وخادم SQL على الاستضافة) |
| أسلوب البناء | **Code First** بواسطة Entity Framework Core 10 |
| تتبع التغييرات | **Migrations**: `InitialCreate` (2026-03-22) ثم `AddOperationsTable` (2026-04-04) |
| تطبيق الـ Migrations | تلقائياً عند تشغيل التطبيق (`Database.Migrate()` في `Program.cs`) |
| عدد الجداول | 3 جداول أساسية + `__EFMigrationsHistory` |

### 1.2 الجداول وعلاقاتها

![ERD](<رسومات/03-erd.png>)

- **Authors** ← **Sales**: مؤلف واحد له مبيعات كثيرة.
- **Authors** ← **Operations**: مؤلف واحد له عمليات كثيرة (أو عملية عامة بدون مؤلف).

### 1.3 القيود والفهارس والإعدادات (من `AppDbContext`)

| الإعداد | التفصيل | الغرض |
|---|---|---|
| مفتاح أساسي | `Id` (Identity) في الجداول الثلاثة | تعريف فريد للسجل |
| فهرس فريد | `IX_Authors_Code` على `Code` | منع تكرار كود الدخول |
| فهارس المفاتيح الأجنبية | `IX_Sales_AuthorId`, `IX_Operations_AuthorId` | تسريع الربط والاستعلام |
| `OnDelete(Restrict)` | على المفتاحين الأجنبيين | منع حذف مؤلف له سجلات |
| **Global Query Filter** | `HasQueryFilter(a => !a.IsDeleted)` على `Author` | الحذف الناعم: المؤلف المحذوف يختفي من كل الاستعلامات تلقائياً |
| دقة الأرقام المالية | `decimal(18,2)` | دقة مالية صحيحة |
| قيم افتراضية | `BasicFees=0`, `IsDeleted=false`, `SaleDate/OperationDate=GETUTCDATE()` | قيم آمنة عند الإدخال |
| حقول التتبع | `CreatedAt` / `UpdatedAt` تُضبط بـ `override SaveChangesAsync` | تتبع زمن الإنشاء والتعديل |

![إعداد DbContext](<صور الأكواد/07-dbcontext-config.png>)

### 1.4 التطبيع (Normalization)

- **1NF:** كل الحقول ذرّية (قيمة واحدة) ولا توجد مجموعات متكررة.
- **2NF:** كل جدول له مفتاح أساسي بسيط (`Id`)، فلا اعتماد جزئي.
- **3NF:** بيانات المؤلف (الاسم، الكود) لا تتكرر في المبيعات والعمليات بل تُربط بـ `AuthorId`.
- **قرارات تصميم مقصودة:** اسم الكتاب `BookTitle` والمنفذ `StoreLocation` نصوص حرة (لا جدول كتب/منافذ) لتبسيط الإدخال حسب طلب العميل. كما أن `TotalAmount` عمود مخزَّن (Denormalized) محسوب في الخدمة لتسريع التقارير وتثبيت قيمة العملية وقت تسجيلها.

### 1.5 الحذف

| الكيان | نوع الحذف | السبب |
|---|---|---|
| المؤلفون والمديرون | **ناعم** (`IsDeleted`) | الحفاظ على سجلاتهم التاريخية |
| المبيعات | **نهائي** (Hard Delete) | قرار المتطلبات |
| العمليات | **نهائي** | قرار المتطلبات |

### 1.6 البيانات الأولية (Seeding)

عند أول تشغيل ينشئ `SuperAdminSeeder` حساب SuperAdmin واحداً من الإعدادات (`SuperAdmin:Name/Code/Password`) بشرط أن تكون القيم حقيقية وليست قيماً افتراضية، وتُشفَّر كلمة المرور بـ BCrypt.

### 4.4 خطوات التشغيل

```bash
# 1) استنساخ المشروع
git clone <repo> && cd AlAsma.Admin/AlAsma.Admin

# 2) ضبط الاتصال وبيانات SuperAdmin (يُفضل User Secrets)
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=(localdb)\MSSQLLocalDB;Database=AlAsmaDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True;"
dotnet user-secrets set "SuperAdmin:Name"     "Super Admin"
dotnet user-secrets set "SuperAdmin:Code"     "<كود>"
dotnet user-secrets set "SuperAdmin:Password" "<كلمة مرور قوية>"

# 3) التشغيل (تُطبَّق الـ Migrations وينشأ SuperAdmin تلقائياً)
dotnet run
# ثم افتح  http://localhost:5133  أو  https://localhost:7165
```

للنشر على الاستضافة: `dotnet publish -c Release` ثم رفع الملفات وضبط نص الاتصال كمتغير بيئة.
