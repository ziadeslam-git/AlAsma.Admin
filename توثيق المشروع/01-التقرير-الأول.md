## 2. تعريف المشروع

«AlAsma.Admin» نظام ويب متكامل يدير الجانب الإداري والمالي لدار نشر وتوزيع كتب («دار الأسمى للنشر والتوزيع»). يعمل النظام عبر المتصفح، وبواجهة عربية كاملة من اليمين لليسار (RTL)، ويغطي الأنشطة التالية:

1. **إدارة المؤلفين وعقودهم:** بيانات المؤلف، كود الدخول، تاريخ بداية ونهاية العقد، والمصروفات الأساسية (`BasicFees`) المحمّلة على المؤلف، مع حساب تلقائي لحالة العقد (نشط / ينتهي قريباً / منتهي / غير محدد) وعدد الأيام المتبقية.
2. **تسجيل مبيعات الكتب:** كل عملية بيع تُسجَّل باسم الكتاب والمؤلف والسعر والكمية والمنفذ (مكان البيع) وتاريخ البيع، ويحسب النظام صافي العملية تلقائياً.
3. **تسجيل العمليات التشغيلية والمصروفات:** مثل الطباعة والتصميم وإيجار المخازن، وربطها بمؤلف أو بكتاب أو تسجيلها كنفقة عامة.
4. **لوحات المتابعة (Dashboards):** لوحة للإدارة (مؤشرات المبيعات والعقود)، ولوحة شخصية لكل مؤلف يرى فيها مبيعاته وصافي ربحه.
5. **التقارير والتصدير:** تقارير المبيعات والعمليات وتقرير تفصيلي لكل مؤلف قابل للتنزيل بصيغة Word أو PDF.
6. **الصلاحيات:** ثلاثة أدوار (SuperAdmin / Admin / Author) لكل منها صلاحيات محددة، والدخول بالكود وكلمة المرور.

> **الفكرة الأساسية:** استبدال الأعمال اليدوية (دفاتر وجداول منفصلة) بنظام مركزي يعطي الإدارة رؤية مالية واضحة، ويعطي المؤلف شفافية كاملة في مبيعاته وأرباحه.

## 3. أهداف المشروع

### 3.1 الهدف العام
توفير نظام ويب موثوق لإدارة المؤلفين والمبيعات والمصروفات وحساب الأرباح الصافية، وتقديم رؤية مالية واضحة للإدارة وللمؤلفين معاً.

### 3.2 الأهداف التفصيلية

| # | الهدف | كيف يتحقق في النظام |
|---|---|---|
| 1 | مركزية بيانات المؤلفين والعقود | جدول `Authors` وشاشات إضافة/تعديل/حذف المؤلفين (للـ SuperAdmin) |
| 2 | تتبع انتهاء العقود مبكراً | حالة العقد + الأيام المتبقية + عداد تنازلي حي + قائمة «عقود تنتهي قريباً» في لوحة الإدارة |
| 3 | تسجيل المبيعات بدقة وبدون أخطاء حسابية | حساب `TotalAmount` في طبقة الخدمة فقط (لا يأتي من الواجهة) |
| 4 | احتساب المصروفات والعمليات التشغيلية | جدول `Operations` وصفحة العمليات مع بحث وتصدير |
| 5 | حساب صافي الربح للمؤلف | `صافي الربح = إجمالي المبيعات − المصروفات الأساسية − مصروفات العمليات` |
| 6 | الشفافية للمؤلف | لوحة شخصية للمؤلف تعرض مبيعاته وعقده وأرباحه فقط |
| 7 | الحماية والتحكم في الصلاحيات | Cookie Authentication + أدوار + `[Authorize(Roles=...)]` + تشفير كلمات المرور بـ BCrypt |
| 8 | التقارير القابلة للتصدير | تصدير Word وPDF حقيقي (A4 عربي RTL) |
| 9 | سهولة الاستخدام على كل الأجهزة | واجهة متجاوبة (موبايل / ديسكتوب) ووضع ليلي (Dark Mode) |
| 10 | قابلية الصيانة والتوسع | معمارية طبقية: Controller ← Service ← Repository/UnitOfWork ← DbContext |

## 4. الجهة المستفيدة من المشروع

| الجهة | نوع الاستفادة |
|---|---|
| **دار الأسمى للنشر والتوزيع (الإدارة العليا — SuperAdmin)** | تحكم كامل في الحسابات والمؤلفين والبيانات المالية، ورؤية شاملة لأداء الدار |
| **مديرو الدار (Admin)** | إدارة العمل اليومي: تسجيل المبيعات والعمليات ومتابعة المؤلفين والتقارير بدلاً من SuperAdmin |
| **المؤلفون (Author)** | معرفة مبيعات كتبهم وحالة عقودهم وصافي أرباحهم بشفافية وفي أي وقت |
| **المحاسب / المسؤول المالي** | تقارير جاهزة للمبيعات والمصروفات وتصديرها |
| **منافذ البيع** (مكتبات / واتساب / مكتب رئيسي) | تُسجَّل كحقل «المنفذ» لتحليل أماكن البيع |

## 5. الهيكل التنظيمي للمشروع

### 5.1 الهيكل التنظيمي للمستخدمين (الصلاحيات)

| **Author** | عدة حسابات | SuperAdmin | يرى لوحته الشخصية ويصدّر تقريره فقط |

### 5.2 الهيكل التنظيمي للنظام برمجياً (طبقات المشروع)

![المعمارية](<رسومات/02-architecture.png>)

```
AlAsma.Admin/
├─ Program.cs                 نقطة التشغيل: DI + المصادقة + المسارات
├─ Models/                    الكيانات: BaseEntity, Author, Sale, Operation
├─ Data/                      AppDbContext + Migrations + Seeder
├─ Interfaces/                العقود: IRepository, IUnitOfWork, I...Service
├─ Repositories/              GenericRepository<T>, UnitOfWork
├─ Services/                  المنطق: AuthorService, SaleService, OperationService, DashboardService, ExportService
├─ DTOs/                      نماذج نقل البيانات (Create / Edit / List / Dashboard)
├─ Controllers/               AccountController, ErrorController
├─ Areas/
│   ├─ SuperAdmin/            إدارة الـ Admins + لوحة SuperAdmin
│   ├─ Admin/                 المؤلفون + المبيعات + العمليات + لوحة الإدارة
│   └─ Author/                لوحة المؤلف
├─ Views/Shared/              _Layout, _Navbar, _Footer, _Notifications
└─ wwwroot/                   css, js, images (logo.png), lib
```

| الطبقة | المسؤولية |
|---|---|
| **Controller** | استقبال الطلب والتحقق من الصلاحية وحالة النموذج (ModelState) ثم استدعاء الخدمة |
| **Service** | قواعد العمل والحسابات المالية (مثل `CalculateTotal`) |
| **Repository / Unit of Work** | الوصول للبيانات وحفظ التغييرات كوحدة واحدة |
| **DbContext** | الاتصال بقاعدة بيانات SQL Server عبر Entity Framework Core |
| **View (Razor)** | عرض النتائج للمستخدم |

## 7. البرمجة الكائنية (OOP) في المشروع

المشروع مكتوب بلغة C# وهي لغة كائنية التوجه بالكامل. فيما يلي المبادئ الأربعة للبرمجة الكائنية مع أمثلة **من كود المشروع الفعلي**.

### 7.1 الفئة (Class) والكائن (Object)

- **الفئة** قالب يعرّف الخصائص والدوال، مثل `Author` و`Sale` و`Operation`.
- **الكائن** نسخة فعلية من الفئة تُنشأ وقت التشغيل، مثل:

```csharp
var sale = new Sale { BookTitle = dto.BookTitle, SalePrice = dto.SalePrice, Quantity = dto.Quantity, ... };
```
كل صف في جدول `Sales` يقابله كائن من الفئة `Sale`، وتُنشأ كائنات الخدمات (`SaleService`) عبر حاقن التبعيات (Dependency Injection) عند كل طلب.

![فئة Sale](<صور الأكواد/05-model-sale.png>)

### 7.2 التغليف (Encapsulation)

حماية الحالة الداخلية للكائن وإتاحتها عبر واجهة عامة فقط:

- الحقول الداخلية في الخدمات `private readonly IUnitOfWork _unitOfWork` لا يمكن للخارج الوصول لها مباشرة.
- دالة حساب الإجمالي `CalculateTotal` معرّفة `private` داخل `SaleService`؛ فلا يستطيع أي Controller أو View تغيير طريقة الحساب بل يستدعي `CreateSaleAsync` فقط. (هذه قاعدة ذهبية في المشروع: `TotalAmount` يُحسب في الخدمة فقط).
- الخاصيتان `ContractStatus` و`DaysRemaining` في الفئة `Author` خاصيتان للقراءة فقط (`get`) محسوبتان من `ContractEnd` ومعلّمتان `[NotMapped]` فلا تُخزَّنان في القاعدة.
- كلمة المرور تُخزَّن كـ Hash (`BCrypt`) وليس نصاً صريحاً.

![فئة Author](<صور الأكواد/04-model-author.png>)

### 7.3 التجريد (Abstraction)

إخفاء التفاصيل المعقدة وتقديم واجهة بسيطة:

- الواجهات `IAuthorService` و`ISaleService` و`IOperationService` و`IDashboardService` و`IExportService` تعرّف **ماذا** تفعل الخدمة دون **كيف**. الـ Controller يتعامل مع الواجهة فقط.
- `IRepository<T>` و`IUnitOfWork` يخفيان تفاصيل Entity Framework وSQL عن الخدمات.

![الواجهة IRepository](<صور الأكواد/15-irepository-interface.png>)

### 7.4 الوراثة (Inheritance)

- الفئات `Author` و`Sale` و`Operation` **ترث** من الفئة الأب `BaseEntity` فتحصل على `Id` و`CreatedAt` و`UpdatedAt` دون تكرار.
- `GenericRepository<T>` يرث/ينفّذ `IRepository<T>` بقيد `where T : BaseEntity`.
- كل Controller يرث من `Controller`، و`AppDbContext` يرث من `DbContext`.

```csharp
public abstract class BaseEntity { public int Id {get;set;} public DateTime CreatedAt {get;set;} public DateTime UpdatedAt {get;set;} }
public class Author : BaseEntity { ... }
public class Sale   : BaseEntity { ... }
```

![BaseEntity](<صور الأكواد/03-model-baseentity.png>)

### 7.5 تعدد الأشكال (Polymorphism)

- **تعدد الأشكال عبر الواجهات:** يُسجَّل في `Program.cs` أن `IUnitOfWork` ينفَّذ بـ `UnitOfWork`، و`ISaleService` بـ `SaleService`؛ ويمكن استبدال التنفيذ (مثلاً لأغراض الاختبار) دون تعديل الـ Controller.
- **الإلغاء (Overriding):** `AppDbContext` يعيد تعريف (`override`) الدالة `SaveChangesAsync` لضبط `CreatedAt/UpdatedAt` تلقائياً قبل الحفظ.
- **التحميل الزائد (Overloading):** في `AuthorController` توجد `Create()` (عرض النموذج) و`Create(AuthorCreateDto)` (حفظ البيانات)، وكذلك `Edit` و`Delete`.
- **النوع العام (Generics):** `GenericRepository<T>` يعمل مع `Author` و`Sale` و`Operation` بنفس الكود.

![تغليف/تعدد الأشكال في DbContext](<صور الأكواد/08-dbcontext-savechanges.png>)

### 7.6 ملخص

| المبدأ | المثال في المشروع | الفائدة |
|---|---|---|
| التغليف | `private CalculateTotal`, `[NotMapped] ContractStatus`, Hash كلمة المرور | حماية البيانات والحسابات من التعديل الخاطئ |
| التجريد | `ISaleService`, `IRepository<T>`, `IUnitOfWork` | فصل «ماذا» عن «كيف» وتسهيل الاختبار والتغيير |
| الوراثة | `BaseEntity ← Author/Sale/Operation` | إعادة استخدام الكود |
| تعدد الأشكال | Interfaces + DI، `override SaveChangesAsync`، Overloading، Generics | مرونة وقابلية للتوسع |
